# Session Report

## What This Session Was About

The user reported that the codegraph indexing tool kept crashing with a `Fatal process out of memory: Zone` error, even after raising the allocated memory to 12288MB. They asked me to investigate the actual memory usage to find any other cause.

## What Was Handled

I reproduced the crash and measured real memory usage during indexing. Key findings:

- The crash happened at roughly 440 files indexed, consistently, regardless of the heap limit setting (2048MB, 4096MB, or 12288MB all crashed at the same point).
- Peak physical memory at crash was only about 2.9GB — far below the 12GB heap limit the user had set.
- Committed memory at crash was about 9.7GB, below the machine's 12.3GB limit.
- The crash is a native V8 allocator abort, not a JavaScript heap exhaustion. It cannot be caught by the tool's own error handling.

I traced the issue through the tool's worker-thread architecture, the WASM grammar loading, and the V8 Zone allocator used during parsing. I also ran controlled tests to rule out worker recycling, grammar loading, and specific problem files as causes.

## Important Choices

The decisive step was searching for known issues rather than continuing to chase memory thresholds. This surfaced the actual root cause: a known V8 WASM JIT (turboshaft) Zone allocator bug affecting Node.js 22 and 24.

The codegraph project had already shipped a fix for exactly this crash in version 0.9.3, which launches with a V8 flag that keeps grammar compilation off the optimizing tier. The installed version was 0.9.2 — one version behind the fix — and its bundled Node.js v24.16.0 is affected by the bug.

## Current State

The installed codegraph version (0.9.2) does not contain the fix. The indexing still crashes at the same point. The user's memory workaround (raising the heap to 12288MB) is still in place but is ineffective and wasteful on a 16GB machine.

## What Still Needs Attention

The memory workaround should be reverted since it does not address the root cause. The actual fix requires upgrading codegraph to version 0.9.3 or later (the latest is 1.5.0).

## Suggested Next Steps

- Upgrade codegraph to version 0.9.3 or newer, which contains the fix for the Zone OOM crash.
- Remove the `--max-old-space-size=12288` workaround from the shell function and MCP environment variable, since it is unnecessary and reserves excessive memory.
- Re-run the indexing after the upgrade to confirm the crash is resolved.
